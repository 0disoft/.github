This is the default governance model for repositories owned by 0disoft. If a repository has its own `GOVERNANCE.md`, the repository-specific governance model takes precedence.

GitHub does not automatically inherit this file. The default contribution guide links here so contributors can find the shared policy.

## Model

Projects are maintainer-led unless stated otherwise.

The maintainer is responsible for project direction, scope, releases, issue management, pull request review, and final decisions.

## Roles

### Maintainer

A maintainer may:

- define project scope and priorities
- review and merge pull requests
- close issues and discussions
- publish releases
- update project policies
- enforce the code of conduct

### Contributor

A contributor may:

- open issues
- suggest improvements
- submit pull requests
- improve documentation
- participate in technical discussions

Contribution does not automatically grant maintainer access.

### User

A user may:

- use the project
- report bugs
- request features
- ask questions through supported channels

## Decision-Making

Decisions are made by the maintainer after considering project goals, user impact, maintenance cost, technical tradeoffs, and available time.

Consensus is welcome, but not required for every decision.

The maintainer may decline changes that are outside the project scope, increase maintenance burden too much, or conflict with the project's direction.

## Repository-Specific Governance

Some repositories may have different maintainers, decision rules, release processes, or contribution models. In those cases, the repository-specific governance document takes precedence.
