# 贡献指南

语言: [English](../../../CONTRIBUTING.md) | [한국어](../ko/CONTRIBUTING.md) | [Español](../es/CONTRIBUTING.md) | [Français](../fr/CONTRIBUTING.md) | [हिन्दी](../hi/CONTRIBUTING.md) | 简体中文

感谢你考虑为 0disoft 项目做出贡献。

这是适用于 0disoft 所有仓库的默认贡献指南。如果某个仓库有自己的 `CONTRIBUTING.md`，则以该仓库的专用贡献指南为准。

有关维护者的职责和决策方式，请参阅[治理模式](./GOVERNANCE.md)。

## 贡献之前

在新建 issue 或 pull request 之前，请先查看仓库的 README、现有 issues 和已打开的 pull requests。

对于较大的改动，请先创建 issue，以便在开始实现之前讨论改动范围和方向。

如果发现安全漏洞，请不要创建公开 issue。请按照 `SECURITY.md` 中的说明处理。

## Issues

Issues 适用于以下情况：

- 可复现的 bugs
- 范围明确的功能请求
- 文档问题
- 可能对其他用户也有帮助的项目相关问题

创建 issue 时，请包含以下信息：

- 你期望发生什么
- 实际发生了什么
- 如果适用，请提供复现问题的步骤
- 相关日志、截图、版本信息或运行环境细节

每个 issue 应只聚焦于一个问题或一个请求。

## Pull Requests

欢迎提交范围清晰、便于审查的 pull requests。

在创建 pull request 之前，请确认：

- 尽量保持改动范围较小
- 说明为什么需要这个改动
- 在相关情况下补充测试或文档
- 避免无关的重构
- 遵循仓库中的专用说明

如果 pull request 超出项目范围、改动过大而难以安全审查，或与仓库的发展方向不一致，可能会被拒绝。

## 仓库专用说明

构建命令、测试命令、发布规则、架构说明、依赖策略和部署说明，应写在各仓库的 README 或该仓库专用的 `CONTRIBUTING.md` 中。
