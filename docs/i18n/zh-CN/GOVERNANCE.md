# 治理模式

语言: [English](../../../GOVERNANCE.md) | [한국어](../ko/GOVERNANCE.md) | [Español](../es/GOVERNANCE.md) | [Français](../fr/GOVERNANCE.md) | [हिन्दी](../hi/GOVERNANCE.md) | 简体中文

这是适用于 0disoft 所有仓库的默认治理模式。如果某个仓库有自己的 `GOVERNANCE.md`，则以该仓库的专用治理模式为准。

GitHub 不会自动继承此文件。默认贡献指南会链接到本文档，方便贡献者找到共用政策。

## 模式

除非另有说明，项目由维护者主导。

维护者负责项目方向、项目范围、版本发布、issue 管理、pull request 审查，以及最终决策。

## 角色

### 维护者

维护者可以：

- 定义项目范围和优先级
- 审查并合并 pull requests
- 关闭 issues 和讨论
- 发布 releases
- 更新项目政策
- 执行行为准则

### 贡献者

贡献者可以：

- 创建 issues
- 提出改进建议
- 提交 pull requests
- 改进文档
- 参与技术讨论

参与贡献并不会自动获得维护者权限。

### 用户

用户可以：

- 使用项目
- 报告 bugs
- 请求新功能
- 通过支持的渠道提出问题

## 决策方式

决策由维护者在综合考虑项目目标、用户影响、维护成本、技术取舍和可用时间后作出。

欢迎达成共识，但并非每个决策都必须依赖共识。

如果某项改动超出项目范围、显著增加维护负担，或与项目方向不一致，维护者可以拒绝该改动。

## 仓库专用治理

某些仓库可能有不同的维护者、决策规则、发布流程或贡献模式。在这些情况下，以该仓库的专用治理文档为准。
