# योगदान मार्गदर्शिका

भाषा: [English](../../../CONTRIBUTING.md) | [한국어](../ko/CONTRIBUTING.md) | [Español](../es/CONTRIBUTING.md) | [Français](../fr/CONTRIBUTING.md) | हिन्दी | [简体中文](../zh-CN/CONTRIBUTING.md)

0disoft परियोजना में योगदान देने पर विचार करने के लिए धन्यवाद।

यह 0disoft के स्वामित्व वाले रिपॉज़िटरी के लिए डिफ़ॉल्ट योगदान मार्गदर्शिका है। यदि किसी रिपॉज़िटरी में अपना `CONTRIBUTING.md` है, तो उसी रिपॉज़िटरी की योगदान मार्गदर्शिका को प्राथमिकता दी जाएगी।

Maintainer की भूमिकाओं और निर्णय लेने की प्रक्रिया के लिए [गवर्नेंस](./GOVERNANCE.md) देखें।

## योगदान देने से पहले

नया issue या pull request खोलने से पहले कृपया रिपॉज़िटरी का README, मौजूदा issues और मौजूदा pull requests देख लें।

बड़े बदलावों के लिए, पहले एक issue खोलें ताकि लागू करने से पहले काम के दायरे और दिशा पर चर्चा की जा सके।

सुरक्षा कमजोरियों के लिए सार्वजनिक issue न खोलें। इसके बजाय `SECURITY.md` का पालन करें।

## Issues

Issues का उपयोग इन मामलों में करें:

- दोहराए जा सकने वाले bugs
- स्पष्ट दायरे वाली feature requests
- दस्तावेज़ीकरण से जुड़ी समस्याएँ
- परियोजना से जुड़े ऐसे प्रश्न जो अन्य उपयोगकर्ताओं के लिए भी उपयोगी हो सकते हैं

Issue खोलते समय ये जानकारी शामिल करें:

- आपको क्या होने की अपेक्षा थी
- वास्तव में क्या हुआ
- यदि लागू हो, तो समस्या को दोहराने के चरण
- संबंधित logs, screenshots, versions या environment details

हर issue को एक ही समस्या या अनुरोध पर केंद्रित रखें।

## Pull Requests

ऐसे pull requests स्वागत योग्य हैं जिनका दायरा स्पष्ट हो और जिनकी समीक्षा करना आसान हो।

Pull request खोलने से पहले:

- बदलाव को यथासंभव छोटा रखें
- समझाएँ कि यह बदलाव क्यों ज़रूरी है
- जहाँ उचित हो, tests या documentation शामिल करें
- असंबंधित refactoring से बचें
- यदि रिपॉज़िटरी में अलग निर्देश दिए गए हैं, तो उनका पालन करें

Pull request को अस्वीकार किया जा सकता है यदि वह परियोजना के दायरे से बाहर हो, सुरक्षित रूप से समीक्षा करने के लिए बहुत बड़ा हो, या रिपॉज़िटरी की दिशा से मेल न खाता हो।

## रिपॉज़िटरी-विशिष्ट निर्देश

Build commands, test commands, release rules, architecture notes, dependency policies और deployment instructions हर रिपॉज़िटरी के README या उसके अपने `CONTRIBUTING.md` में लिखे जाने चाहिए।
