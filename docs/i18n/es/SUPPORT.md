# Guía de soporte

Idioma: [English](../../../SUPPORT.md) | [한국어](../ko/SUPPORT.md) | Español | [Français](../fr/SUPPORT.md) | [हिन्दी](../hi/SUPPORT.md) | [简体中文](../zh-CN/SUPPORT.md)

Esta es la guía de soporte predeterminada para los repositorios propiedad de 0disoft. Si un repositorio tiene su propio `SUPPORT.md`, tendrá prioridad la guía de soporte específica de ese repositorio.

## Antes de pedir ayuda

Revisa primero el README del repositorio, la documentación y los issues existentes.

## Dónde preguntar

Usa el canal más adecuado según el caso:

- Bugs: abre un issue en GitHub e incluye los pasos para reproducir el problema.
- Solicitudes de funciones: abre un issue en GitHub describiendo el problema y el resultado esperado.
- Preguntas de uso: usa GitHub Discussions si el repositorio tiene Discussions habilitado.
- Problemas de documentación: abre un issue en GitHub o envía un pull request.
- Vulnerabilidades de seguridad: sigue las instrucciones de `SECURITY.md`.

## Qué incluir

Al pedir ayuda, incluye:

- qué estás intentando hacer
- qué esperabas que ocurriera
- qué ocurrió realmente
- pasos para reproducir el problema
- logs, capturas de pantalla, versiones o detalles del entorno que sean relevantes

## Qué no está cubierto

Es posible que los mantenedores no puedan ofrecer:

- consultoría privada
- soporte urgente para entornos de producción
- depuración de código de terceros no relacionado
- soporte para versiones modificadas o no admitidas
- soporte para repositorios archivados o experimentales

El soporte se ofrece en la medida de lo posible.
