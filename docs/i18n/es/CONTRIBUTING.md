# Guía de contribución

Idioma: [English](../../../CONTRIBUTING.md) | [한국어](../ko/CONTRIBUTING.md) | Español | [Français](../fr/CONTRIBUTING.md) | [हिन्दी](../hi/CONTRIBUTING.md) | [简体中文](../zh-CN/CONTRIBUTING.md)

Gracias por considerar contribuir a un proyecto de 0disoft.

Esta es la guía de contribución predeterminada para los repositorios propiedad de 0disoft. Si un repositorio tiene su propio `CONTRIBUTING.md`, tendrá prioridad la guía específica de ese repositorio.

Consulta [Gobernanza](./GOVERNANCE.md) para conocer las funciones de los mantenedores y cómo se toman las decisiones.

## Antes de contribuir

Antes de abrir un nuevo issue o pull request, revisa primero el README del repositorio, los issues existentes y los pull requests ya abiertos.

Para cambios más grandes, abre primero un issue para que el alcance y la dirección puedan discutirse antes de empezar la implementación.

Para vulnerabilidades de seguridad, no abras un issue público. Sigue las instrucciones de `SECURITY.md`.

## Issues

Usa los issues para:

- errores reproducibles
- solicitudes de funciones con un alcance claro
- problemas de documentación
- preguntas específicas del proyecto que puedan ayudar a otros usuarios

Al abrir un issue, incluye:

- qué esperabas que ocurriera
- qué ocurrió realmente
- pasos para reproducir el problema, si corresponde
- registros, capturas de pantalla, versiones o detalles del entorno que sean relevantes

Mantén cada issue centrado en un solo problema o solicitud.

## Pull Requests

Los pull requests son bienvenidos cuando tienen un alcance claro y son fáciles de revisar.

Antes de abrir un pull request:

- mantén el cambio tan pequeño como sea razonablemente posible
- explica por qué el cambio es necesario
- incluye pruebas o documentación cuando sea relevante
- evita refactorizaciones no relacionadas
- sigue cualquier instrucción específica del repositorio

Un pull request puede ser rechazado si queda fuera del alcance del proyecto, es demasiado amplio para revisarlo con seguridad o entra en conflicto con la dirección del repositorio.

## Instrucciones específicas del repositorio

Los comandos de compilación, comandos de prueba, reglas de publicación, notas de arquitectura, políticas de dependencias e instrucciones de despliegue deben documentarse en el README de cada repositorio o en su `CONTRIBUTING.md` específico.
