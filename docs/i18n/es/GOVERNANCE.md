# Gobernanza

Idioma: [English](../../../GOVERNANCE.md) | [한국어](../ko/GOVERNANCE.md) | Español | [Français](../fr/GOVERNANCE.md) | [हिन्दी](../hi/GOVERNANCE.md) | [简体中文](../zh-CN/GOVERNANCE.md)

Este es el modelo de gobernanza predeterminado para los repositorios propiedad de 0disoft. Si un repositorio tiene su propio `GOVERNANCE.md`, tendrá prioridad el modelo de gobernanza específico de ese repositorio.

GitHub no hereda este archivo automáticamente. La guía de contribución predeterminada enlaza aquí para que los colaboradores puedan encontrar la política compartida.

## Modelo

Salvo que se indique lo contrario, los proyectos están dirigidos por sus mantenedores.

El mantenedor es responsable de la dirección del proyecto, su alcance, las publicaciones, la gestión de issues, la revisión de pull requests y las decisiones finales.

## Roles

### Mantenedor

Un mantenedor puede:

- definir el alcance y las prioridades del proyecto
- revisar y fusionar pull requests
- cerrar issues y conversaciones
- publicar releases
- actualizar las políticas del proyecto
- aplicar el código de conducta

### Contribuidor

Un contribuidor puede:

- abrir issues
- sugerir mejoras
- enviar pull requests
- mejorar la documentación
- participar en conversaciones técnicas

Contribuir al proyecto no concede automáticamente acceso como mantenedor.

### Usuario

Un usuario puede:

- utilizar el proyecto
- reportar bugs
- solicitar nuevas funciones
- hacer preguntas a través de los canales admitidos

## Toma de decisiones

Las decisiones las toma el mantenedor después de considerar los objetivos del proyecto, el impacto en los usuarios, el coste de mantenimiento, los compromisos técnicos y el tiempo disponible.

El consenso es bienvenido, pero no es obligatorio para cada decisión.

El mantenedor puede rechazar cambios que queden fuera del alcance del proyecto, aumenten demasiado la carga de mantenimiento o entren en conflicto con la dirección del proyecto.

## Gobernanza específica del repositorio

Algunos repositorios pueden tener mantenedores, reglas de decisión, procesos de publicación o modelos de contribución diferentes. En esos casos, tendrá prioridad el documento de gobernanza específico del repositorio.
