Thanks for considering a contribution to a 0disoft project.

This is the default contribution guide for repositories owned by 0disoft. If a repository has its own `CONTRIBUTING.md`, the repository-specific guide takes precedence.

See [Governance](./GOVERNANCE.md) for maintainer roles and decision-making.

## Before Contributing

Please check the repository README, existing issues, and existing pull requests before opening a new issue or pull request.

For larger changes, open an issue first so the scope and direction can be discussed before implementation.

For security vulnerabilities, do not open a public issue. Follow `SECURITY.md` instead.

## Issues

Use issues for:

- reproducible bugs
- focused feature requests
- documentation problems
- project-specific questions that may help other users

When opening an issue, include:

- what you expected to happen
- what actually happened
- steps to reproduce the problem, if applicable
- relevant logs, screenshots, versions, or environment details

Keep each issue focused on one problem or request.

## Pull Requests

Pull requests are welcome when they are focused and easy to review.

Before opening a pull request:

- keep the change as small as practical
- explain why the change is needed
- include tests or documentation when relevant
- avoid unrelated refactoring
- follow any repository-specific instructions

A pull request may be declined if it is outside the project scope, too broad to review safely, or conflicts with the repository's direction.

## Repository-Specific Instructions

Build commands, test commands, release rules, architecture notes, dependency policies, and deployment instructions belong in each repository's README or repository-specific `CONTRIBUTING.md`.
